# Lecciones Aprendidas & Reglas de Ingeniería (BenFlex)

## 1. Seguridad de E-Commerce & Postura OWASP / ASVS
- **Cero Confianza en Precios del Cliente (Zero Client Trust):** Nunca aceptar `total`, `subtotal`, `unitPrice`, `transferDiscount` ni `status` desde el payload HTTP del navegador en `POST /api/orders`. El servidor siempre debe recalcular importes leyendo `base_price`, `variations` y `transfer_discount_percent` desde PostgreSQL dentro de la transacción.
- **Control de Acceso Administrativo (`HttpOnly` + `SameSite=Strict`):** Jamás declarar contraseñas ni claves en archivos con `'use client'` ni variables `NEXT_PUBLIC_*`. Validar credenciales exclusivamente en Route Handlers usando `crypto.timingSafeEqual` y cookies firmadas con HMAC-SHA256.
- **Protección de PII y Anti-IDOR (`BOLA`):** `GET /api/orders` solo debe responder a sesiones administrativas autenticadas. Para la pantalla pública `/order-confirmation`, utilizar identificadores no secuenciales (`BF-<HEX>`) combinados con un `accessToken` criptográfico de 128 bits verificado en tiempo constante en `GET /api/orders/[id]?token=...`.
- **Cumplimiento PCI-DSS SAQ-A:** Nunca renderizar `<input>` propios para números de tarjeta (PAN), vencimiento o CVV en formularios propios; delegar siempre la captura a links/pasarelas oficiales encriptadas.
- **Defensa en Profundidad en Supabase:** Toda tabla en el esquema `public` (`benflex_products`, `benflex_orders`, `benflex_inquiries`) debe tener `ENABLE ROW LEVEL SECURITY` activo para impedir acceso directo no autorizado vía PostgREST (`anon` key).

## 2. Consistencia Transaccional, Stock y Redondeo en Next.js 16
- **Concurrencia de Stock sin Deadlocks:** Agrupar cantidades por `productId`, ordenar los IDs alfabéticamente antes de ejecutar `SELECT ... FOR UPDATE`, descontar stock dentro de `BEGIN ... COMMIT` y restaurarlo automáticamente si el pedido pasa a `CANCELADO`.
- **Idempotencia en Checkout:** Enviar un `idempotencyKey` (`UUID`) único por intento de compra y esperar (`await`) la confirmación `201/200` del servidor antes de vaciar el carrito (`clearCart()`), evitando pérdidas de carrito ante errores de red o falta de stock (`HTTP 409`).
- **Redondeo Exacto en Pesos (ARS):** Calcular el descuento por transferencia a nivel unitario (`unitTransfer = Math.round(unitPrice * (1 - pct / 100))`) tanto en el carrito como en PostgreSQL para asegurar `$0` de diferencia entre la suma de líneas y el total final.
- **Frontera Server/Client en App Router:** No importar funciones utilitarias desde módulos marcados con `'use client'` dentro de código de servidor (`src/lib/db.ts`); mantener helpers puros en módulos de servidor o compartidos sin `'use client'`.

## 3. Resiliencia en Carga de Catálogo (ATM) y Analítica de Ventas
- **Persistencia Híbrida Desacoplada:** El catálogo y la creación de productos nunca deben quedar bloqueados por la ausencia de variables de base de datos en local o problemas temporales de conectividad externa. Implementar siempre una capa de almacenamiento local sincronizada (`src/lib/localStore.ts` con archivo `local_storage.json`) que actúe de respaldo transparente para que el dueño y desarrollador puedan operar sin interrupciones.
- **Compresión Previa de Imágenes en Cliente:** Las fotos subidas desde dispositivos móviles o cámaras de alta resolución superan fácilmente los límites de payload HTTP. Redimensionar y comprimir en `<canvas>` (ancho máximo 850px, calidad JPEG 0.75) antes de generar el base64, garantizando que el archivo sea ultraligero (< 300 KB).
- **Feedback Visual Inline en Modales:** Los mensajes de error de API (`400/500`) no deben depender únicamente de notificaciones Toast que pueden quedar ocultas tras un modal abierto; renderizar alertas inline destacadas en el formulario para indicar al usuario con precisión qué campo corregir.
- **Exportación Segura con BOM UTF-8:** Al generar archivos CSV desde el navegador para apertura en Microsoft Excel o Google Sheets, anteponer siempre el carácter de orden de bytes `\uFEFF` para evitar problemas de codificación con tildes, eñes y caracteres en español.

## 4. Disciplina de Control de Versiones (Git) y Despliegue en VPS (DonWeb)
- **Commit y Push Obligatorio por Modificación:** Cada cambio, corrección o nueva funcionalidad verificada debe ser inmediatamente registrada con `git commit` descriptivo (Conventional Commits) y sincronizada con `git push origin main` sin excepción.
- **Cookies de Sesión detrás de Reverse Proxy (Nginx):** En producción sobre VPS, evaluar `X-Forwarded-Proto` para el atributo `Secure` de las cookies `HttpOnly`. Esto permite operar el panel `/admin` tanto por HTTP (mientras propaga el DNS del dominio en DonWeb) como por HTTPS una vez emitido el certificado de Let's Encrypt.
- **Preservación de Base de Datos Híbrida en Deploy (`Zero Data Loss`):** Los scripts de actualización (`deploy/setup-vps.sh` y `deploy/update-vps.sh`) deben respaldar y restaurar `src/data/local_storage.json` antes de ejecutar `git reset --hard origin/main`, garantizando que los productos y ventas creados en producción nunca se sobrescriban.
- **Regla de Hooks en Pantallas con Bloqueo de Sesión (`Rules of Hooks`):** En componentes Client (`'use client'`) que poseen early returns condicionales por sesión (`if (checkingSession) return ...` o `if (!authRole) return ...`), TODOS los hooks (`useState`, `useEffect`, `useCallback`, `useMemo`) deben declararse estrictamente arriba del primer `if (...) return`. Colocar un `useMemo` debajo de `if (!authRole) return` provoca el error `Rendered more hooks than during the previous render` en cuanto el usuario inicia sesión.
